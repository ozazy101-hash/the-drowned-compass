# Private map generation application

The PartyContent commands reach one owned application. The server alone owns request identity, reservations, private proofs and immutable-object attachment. Client intents select saved parents and canonical integer image-pixel rectangles; they cannot assert geometry registration, proof, digest or provider state. Reference illustration uses a saved version's artwork or retained reference; drawing/reference uploads remain the existing private-version operation.

Live defaults are disabled, quota0/spend0. Concurrency1, provider deadline120s and orphan retention24h are enforced in SQL/application. A configured reservation is a conservative per-request cost allowance, retained after cancellation or uncertain outcome. Nonzero paid settings require a separately approved upper-bound provider cost allowance; these tests establish reservation enforcement, not hosted billing guarantees. The accepted provider adapter never resubmits an unknown request; no approved provider lookup capability exists, so it stays uncertain until independently reconciled or explicitly cancelled. Cancellation cannot undo billing. Queued submission ownership uses an atomic unique token, not a state/revision equality guess.

PREPARE reads owned immutable source/candidate and computes expectedRGBA in a fresh worker. FINALIZE decodes one PNG in a fresh worker. A bounded preflight rejects malformed browser assembly before consuming its write-once canonical object name, allowing same-candidate retry. It grants no attachment authority: after upload, FINALIZE independently re-reads and verifies the exact immutable stored provisional PNG. Completion/recovery checks original proof, immutable object IDs/digests, saved parent/revision and accepting receipt tuple; SQL serializes cancellation and family changes with04 attachment. Nothing selects a presentation. Proofs expire after24h; saved versions remain retained. Expired/failed work may be cancelled and retried with an explicit new intent.

The decoder derives from accepted03 source `8e679aede15bfaa106ab8e5f13dbd672c02f1583`; only the admitted1024squareRGB/RGBA8 noninterlacedPNG20MiB profile is supported. No palette, interlacing, outpainting, resize, flatten or color conversion. Decoder changes only remove probe-only utilities and parameterize the streamed encoded-body bound for trusted PREPARE's two-image input. General manual JPEG/WebP uploads are unchanged.

The entrypoint requires an owned Edge supervisor supporting userWorkers.create. It creates fresh256MB workers with soft1900/hard2000msCPU,150s wall, forceCreate/noModuleCache, oneshot. Every private stage uses a separate loopback HTTP request, authenticated by a non-logged server nonce. Its ingress tag is independent of the outer job command: tagging the outer request and then consuming a worker response before durable SQL caused a real connection abort. The internal ingress returns the worker response directly. It never exposes a public client-authorized proof endpoint.

Hosted migration, runtime topology/IAM/session checks, billing allowance and live enablement are separate final gates. Do not deploy this supervisor entrypoint as an ordinary hosted user function and assume userWorkers or loopback topology works. The final hosted topology must demonstrate fresh bounded private stages before live enablement; no new account, hosted migration or deployment was performed here. Configure MAP_CONTROLLER_ORIGIN and the absolute MAP_VERIFIER_WORKER_PATH for that verified topology. Provider key and Supabase service key remain server-only.

Orphan cleanup is an internal owned maintenance operation (`store.cleanup`), not a client command. After24h it releases only failed/cancelled, unaccepted canonical objects. Its durable pending inventory survives lost cleanup responses; acknowledgement occurs only after removals. Completed proof/candidate/output and every referenced immutable artwork remain retained. Scheduling cleanup and hosted enablement require the later release gate.
