# Bounded ImageMagick WASM Edge comparison

Throwaway ticket03 comparison, not production06 orchestration. No provider calls, credentials, AWS/Supabase hosted calls or shared dependencies. Selected npm package `@imagemagick/magick-wasm@0.0.44`, Apache-2.0, pinned tarball SHA512 and extracted module/default WASM SHA256 in dependency-lock.json. Installer executes no package scripts, writes only ignored probe deps, preserves package LICENSE/NOTICE. Binary dependencies and generated fixtures are intentionally uncommitted; rerun installer/prepare explicitly. No version substitution. Default package `./magick.wasm` resolves to x86 (32-bit WASM linear-memory build); x64 is a separate exported build and was not selected.

[Official Supabase image manipulation example](https://supabase.com/docs/guides/functions/examples/image-manipulation) demonstrates this WASM library and initialization from local WASM bytes. Its example runtime version does not establish hosted compatibility. Measured existing image ID `sha256:c52405002a890ca9fcf77978671c57f3a988e03174afb277f84ac65bc917013c`, Edge v1.74.3, compatible Deno2.1.4/V8 11.6.189.12. [Library source/releases](https://github.com/dlemstra/magick-wasm) and downloaded package metadata identify selected version/license. [Official ImageMagick composition documentation](https://imagemagick.org/compose/) defines Copy as Src with compose:outside-overlay=false; bare Src would clear outside. Crop candidate to selected region, reset page, use Copy at region offset. Output explicitly RGBA8 lossless PNG with compression-level0; no resize, color-space conversion, alpha blending or flattening.

Runner requires existing Docker image and exclusive localhost4195. Readonly mount ONLY this magick probe directory (retained live images copied byte-identically from reviewed Lambda corpus by prepare; synthetic PNGs generated deterministically). Main serves only fixed WASM/fixture allowlist. Actual user-worker memory256MB, softCPU1900ms/hardCPU2000ms, wall150000ms; no relaxed budget. Container2048MiB/no extra swap/one CPU and256MiB tmpfs bound enclosing main/events/user workers; this container limit is separate from user-worker256MB. 60s outer watchdog aborts requests and stops/kills the exact unique owned container, including ambiguous launch results. All Docker CLI calls are asynchronous with explicit deadlines capped by the remaining outer budget; bounded cleanup calls each have1500ms timeouts. Cleanup still runs if evidence capture fails, then removes that container. The cleanup allowance is at most6s beyond the60s operation deadline. No shared cleanup.

Cold means a new user worker, its module initialization and local WASM fetch/compile/load included. Host container/OS file caches may already be warm. Main reuses the identical worker handle only for an eligible live-warm call; policy per_worker does NOT promise CPU budget reset per request. Supervisor execution IDs/events are authoritative. A returned PNG alone cannot establish resource acceptance. Final cold failed, so final warm is explicitly skipped; no verified warm performance.

Canonical contract remains the existing independent Node decoder RGBA bytes. Node tests compare all995776 outside pixels against exact source and all52800 selected pixels against exact raw candidate, including all four channels, transparent hidden RGB, low alpha, noise and retained live images. Those passes demonstrate library semantics in Node only. Worker ingress rejects non-PNG, truncated chunks, APNG frame chunks, invalid bounds and dimensions before library decode; fixed1024square admission is a proposed comparison envelope, separate from outer20MiB/16M upload limits and provider dimension restrictions. This prototype does not implement digest transport, job authorization, ledger, attachment or production error classification.
